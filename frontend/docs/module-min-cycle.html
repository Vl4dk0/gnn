Cycle prediction: moving from local to structural

After degree prediction, the next question was whether the model can recover a less local signal: the shortest cycle containing each node.

What is the label?

For node v, the label is the length of the shortest cycle that contains v. If no such cycle exists, the label is 0.

What changes in the training loop?

The loop structure is the same as degree training. The difference is mainly the label generation: instead of G.degree(i), each label is computed with get_min_cycle(G, i). 

# ai/min_cycle/train.py (simplified)
G = generate_random_graph(...)
y = torch.tensor([get_min_cycle(G, i) for i in range(num_nodes)], dtype=torch.float)
out = model(data).squeeze()
loss = F.mse_loss(out, data.y)
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()

What graphs were used for training and testing?

As in degree prediction, both training and evaluation sample fresh random graphs from the same distribution: n in [5,12], p in [0.15,0.6], self-loop probability 0.1, and 4-dimensional node features. Evaluation uses 100 random graphs during training and 200 random graphs for final metrics.

How well did it work?

Loopy with r=3 clearly outperformed the others in these experiments, which is consistent with its cycle-aware design.
