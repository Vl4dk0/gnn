Degree prediction: first trust check

I started here because degree is local and unambiguous. If a model cannot recover degree reliably, there is no reason to trust it on harder structural properties.

What exactly happens in the training loop?

Each iteration samples a random Erdős-Rényi graph, converts it to PyG, sets label y_v = deg(v), runs a forward pass, computes MSE loss, clips gradients to 1.0, and updates with Adam. During training, evaluation runs on 100 fresh random graphs; final evaluation runs on 200 fresh random graphs. 

# ai/degree/train.py (simplified)
G = generate_random_graph(...)

y = torch.tensor(
    [G.degree(i) for i in range(num_nodes)],
    dtype=torch.float,
)

out = model(data).squeeze()
loss = F.mse_loss(out, data.y)

loss.backward()

torch.nn.utils.clip_grad_norm_(
    model.parameters(),
    max_norm=1.0,
)

optimizer.step()

How are training and test graphs generated?

Training and testing use the same generator family. Default settings are n in [5,12], edge probability p in [0.15,0.6], and self-loop probability 0.1. So reported metrics are out-of-sample on new random graphs from that same distribution.

Node features use four channels: normalized node index, two random channels, and one random channel used as a clustering-like placeholder.

How to read these metrics

Accuracy: exact match rate after rounding predictions to integers.

MAE: average absolute prediction error (same unit as the label).

MSE: average squared prediction error (penalizes large mistakes more than MAE).

Created at: model snapshot creation date from metadata.

Timestamped assesments

As of 2026-02-23: gin_v1 and sage_v1 performed very well (100.00% exact-node accuracy), while gcn_v1 and loopy_r3_v1 were much weaker on this degree setup. This indicates that, in the current experiments, degree prediction behaves like a strongly local counting signal that sum-aggregation models captured best.
