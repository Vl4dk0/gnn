Degree prediction: first trust check

I started here because degree is the most local structural signal. If a model cannot recover this reliably, there is no reason to trust it on more complex graph properties.

What exactly happens in the training loop?

Each step samples a new random Erdős-Rényi graph, converts it to a PyG object, computes node-degree labels directly from NetworkX, runs a forward pass, minimizes MSE, clips gradients, and updates parameters with Adam. This repeats across many randomly generated graphs.

PyG means PyTorch Geometric, the graph tensor format/library used by my models and trainers in this project. 

# ai/degree/train.py (simplified)
G = generate_random_graph(...)
y = torch.tensor([G.degree(i) for i in range(num_nodes)], dtype=torch.float)
out = model(data).squeeze()
loss = F.mse_loss(out, data.y)
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()

How are graphs and features generated?

By default, training graphs use n=5..12 nodes and edge probability p=0.15..0.6. The generator can add self-loops with probability 0.1. Node features use four channels: normalized node index, two random channels, and one random clustering-like channel.

Erdős-Rényi means each possible edge is sampled independently with probability p.

How well did the models solve it?

In saved checkpoints, SAGE and GIN reached perfect rounded-node accuracy, while current GCN and Loopy checkpoints were much weaker.
